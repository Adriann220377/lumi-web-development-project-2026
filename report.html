Project Report

Lumi Architecture Studio Website — Student Portfolio Project · Autumn 2026

01

Planning

The project began with a client brief identifying Lumi Architecture Studio as the target brand. Initial planning involved defining the site architecture — five core pages (Home, Projects, About, Services, Contact) plus this Web Report — and establishing a content hierarchy for each. A wireframe sketch was produced before any visual design decisions were made, ensuring layout logic preceded aesthetic choices.

Colour palette selection was driven by the brand brief: a dark premium theme appropriate for a high-end Nordic architecture practice. Gold accents were chosen to suggest precision and craft without excessive warmth. Typography choices (Montserrat for headings, Inter for body) were validated against readability requirements across all three target breakpoints.

02

Specification

The site is implemented as a multi-page static website using semantic HTML5, modular CSS, and a small amount of vanilla JavaScript for interactivity (navigation behaviour, project filtering, and tabbed report content). No frameworks are used, in order to align with course requirements and demonstrate direct control over markup and styling.

Each page has its own CSS file (home.css, projects.css, about.css, services.css, contact.css, report.css) plus a shared style.css for global typography, colours, and layout primitives. Assets are organised into /img for images and /js for scripts, following a clear, predictable structure.

03

Layout Choices

The primary layout system is CSS Grid at the page level, with Flexbox used for component-internal alignment. Grid is used for project cards, services, team members, and report sections, while Flexbox handles navigation, stats bars, and form alignment.

The hero section uses 100vh height with a stacked content column to ensure vertical centring regardless of viewport height. Section padding and max-width constraints are used to keep text columns readable and consistent across pages.

04

Responsiveness

Three breakpoints are defined:

  • Mobile (~375px): Single-column layout throughout. Project grid becomes one column; stats bars stack.
  • Tablet (~768px): Two-column layouts activate for hero content + image pairs. Project grid becomes two columns.
  • Desktop (~1440px): Full three- and four-column grids. Navigation is a horizontal link row.

Responsiveness is implemented using CSS media queries and grid reflow. No framework utilities are used; all breakpoints are written directly in CSS to keep the implementation transparent.

05

Media

All photography is sourced from Unsplash and stored locally in the /img directory. Images are resized to appropriate dimensions for their usage (hero, project cards, team portraits) to avoid unnecessary file size and layout shift.

Alt text is provided for all meaningful images to support screen reader accessibility. Decorative elements (such as geometric frames) are implemented as styled divs without alt attributes.

06

Scripts & Interactivity

JavaScript is used sparingly to enhance the experience without overwhelming the project:

  • Project filter: category buttons show/hide project cards based on data-category attributes.
  • Report tabs: clicking a tab button swaps the visible content section.

All scripts are written in vanilla JavaScript and kept in the /js directory. No third-party libraries are used.

07

Validation

HTML structure follows semantic conventions: landmark elements (nav, main, section, footer), a single H1 per page, and H2/H3 used for section and sub-section titles. Forms use labels paired with inputs.

Colour contrast was checked against WCAG 2.1 AA requirements for the dark theme. Body text, white text, and gold accents all meet or exceed AA contrast ratios against the charcoal background.

08

Reflection

The decision to build Lumi as a multi-page static site rather than a single-page app kept the project aligned with course expectations and made the structure easier to understand. Navigation is simple and predictable, and each page has a clear purpose.

If the project were extended, future enhancements could include scroll-triggered animations, a richer project detail view with image galleries, and a more advanced map integration using a JavaScript library such as Leaflet with OpenStreetMap tiles.
