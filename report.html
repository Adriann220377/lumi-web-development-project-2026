Project Report

Lumi Architecture Studio Website — Student Portfolio Project · Autumn 2026

01

Planning

I started the project by breaking down what the Lumi Architecture Studio website actually needed: a clean multi‑page structure with Home, Projects, About, Services, Contact, and the Web Report itself. Before touching any visuals, I sketched a rough layout and page hierarchy so I knew how everything connected.

Most of the early planning was just me figuring out how to keep the site simple, readable, and consistent across all pages. I used course material and W3Schools a lot during this phase to make sure I wasn’t missing any basic HTML/CSS structure rules.

For the visual direction, I chose a dark Scandinavian theme with gold accents because it fits the architecture brand. Montserrat and Inter were picked for typography after checking readability on different screen sizes. I tested the fonts manually and adjusted sizes until they felt balanced.

02

Specification

The whole site is built as a static multi‑page website using semantic HTML5, modular CSS, and small amounts of vanilla JavaScript. I didn’t use any frameworks because the course expects us to show understanding of raw HTML/CSS/JS.

Each page has its own CSS file (home.css, projects.css, about.css, services.css, contact.css, report.css) and there’s a shared style.css for global colours, typography, and layout rules.

I kept the folder structure simple:

  • /img for images
  • /js for scripts
  • /css for styles

I used GIMP to crop and resize images so they load faster and don’t break the layout.

03

Layout Choices

I used CSS Grid for the main page layouts (projects, services, team grid, report sections) because it gives clean alignment and predictable spacing. Flexbox is used inside components like navigation, stats bars, and form elements.

The hero sections use a tall layout with centered content so they look good on both large monitors and smaller laptops. I also added max‑width limits to text blocks to keep everything readable and prevent long lines stretching across the screen.

04

Responsiveness

I built the site around three breakpoints:

  • Mobile (~375px): everything becomes a single column, grids collapse, spacing tightens.
  • Tablet (~768px): two‑column layouts activate, images scale down, grids become 2‑columns.
  • Desktop (~1440px): full layout with 3–4 column grids and wide spacing.

All responsiveness is done with CSS media queries. I didn’t use Bootstrap or Tailwind — I wrote everything manually so I could understand how each breakpoint behaves.

Copilot helped me a lot here by explaining certain CSS behaviours and helping me debug weird spacing issues.

05

Media

All images are from Unsplash and stored locally in /img. I resized them in GIMP to avoid huge file sizes and layout shifts.

I added alt text to meaningful images for accessibility. Decorative shapes (gold lines, corner frames, dividers) are done with CSS instead of images so they scale better.

06

Scripts & Interactivity

I kept JavaScript minimal but functional:

  • Navigation behaviour (active link + underline animation)
  • Project filtering using data attributes
  • Tab switching inside the Web Report

Everything is written in vanilla JS. Copilot helped me write cleaner functions and fix a few bugs. Claude was used once or twice when I needed debugging help for layout issues.

No external libraries were used.

07

Validation

I followed semantic HTML rules:

  • One H1 per page
  • Sections grouped logically
  • Labels connected to form inputs
  • Navigation uses proper nav element

I checked colour contrast manually and with online tools to make sure the dark theme still meets accessibility standards. The gold, white, and muted grey colours all pass WCAG AA contrast requirements.

08

Reflection

Building Lumi as a multi‑page static site made everything easier to understand and maintain. Each page has a clear purpose, and navigation feels simple and predictable.

The biggest challenge was responsiveness — especially making the About page and Web Report look good on mobile — but using Copilot, W3Schools, and course material helped me solve those issues step by step.

If I continued the project, I’d add animations, a proper project detail page with galleries, and maybe a more advanced map integration using Leaflet or similar libraries.
